# AFAC 2026 赛题二开发计划

## 项目目标

构建一套可复现、可中断恢复、可评测的金融文档解析流水线，将比赛图片转换为尽可能高保真的 Markdown，并稳定生成符合要求的提交 CSV。

最终目标包括：

1. 在训练集上建立可重复的本地评测流程。
2. 稳定解析 A 榜中的超宽、超密集表格。
3. 控制 API 调用次数、失败率和重复成本。
4. 保存实验配置、模型输出和评分结果，支持多人协作与方案对比。
5. 生成可以直接提交到天池平台的完整结果。

## 当前版本

版本：`v0.1.0`

阶段判断：**端到端工程 MVP 已完成，比赛级表格解析与重建尚未完成。**

### 已完成

- 使用 `uv` 管理 Python 项目和依赖。
- 采用标准 `src/afac_pipeline/` 源码布局。
- 提供 `afac` CLI，包含 `inspect-data`、`extract` 和 `predict` 命令。
- 可直接从原始 ZIP 中读取图片，无需预先解压全部数据。
- 已接通 FinixDoc-VL multipart 图片上传接口。
- 已处理 macOS/Python HTTPS 证书校验问题。
- 支持解析 API 返回的嵌套 Chat Completion JSON。
- 支持图片宽度缩放和纵向重叠切片。
- 支持超时、请求间隔、失败重试和错误记录。
- 支持 `offset`、`limit`、dry-run 和失败后继续运行。
- 支持 Markdown 缓存、断点续跑和无效缓存清理。
- 能生成 `file_name,ground_truth` 格式的 CSV。
- 已有 4 个单元测试，当前全部通过。

### 已验证

- 训练集包含 100 张图片、100 份 Markdown 标注和 100 条映射记录。
- 当前 A 榜压缩包包含 50 张图片。
- 模拟提交包含 100 行，其中 50 个文件名与当前 A 榜数据相交。
- 真实 FinixDoc-VL 请求可以成功完成鉴权、上传和响应解析。
- 图片缩放后的字节会被实际上传，不再误传原始图片。
- 未闭合 Markdown 代码块会被识别为截断响应，不会作为有效缓存保存。

### 当前阻塞

A 榜图片中的宽表无法通过“整页缩放 + 纵向切片”稳定处理：

- 缩放到较小宽度时，文字分辨率不足，API 可能返回空内容。
- 保留较大宽度时，模型生成的 HTML 表格过长，响应容易被截断。
- 纵向切片会保留全部列，并可能切断跨行结构，不能解决宽表问题。
- 当前只有调试图片与错误记录，还没有经过验证的完整 A 榜提交文件。

## 开发路线

### 里程碑 1：二维表格切片

目标版本：`v0.2.0`

任务：

- 统计训练集和 A 榜图片的尺寸、宽高比和像素分布。
- 实现横向与纵向组合的二维切片。
- 支持切片宽度、高度、重叠量和边缘留白配置。
- 在每个横向分块中重复保留表头、首列或关键标识列。
- 保存切片坐标与父图片关系，形成可重建的中间清单。
- 为二维切片的边界、尺寸和顺序补充单元测试。

验收标准：

- 任意宽表可被确定性地切分为有坐标、有顺序的图块。
- 所有图块中的文字保持可识别分辨率。
- 同一配置重复运行得到一致切片结果。

### 里程碑 2：表格结果重建

目标版本：`v0.3.0`

任务：

- 将 API 返回的 Markdown/HTML 表格解析为结构化行列数据。
- 根据切片坐标恢复横向列顺序和纵向行顺序。
- 识别并去除重叠区域造成的重复表头、重复行和重复列。
- 处理 `rowspan`、`colspan`、空单元格和多级表头。
- 对无法可靠合并的分块保留可诊断的中间产物。

验收标准：

- 训练集宽表样本可以重建为语法闭合的 Markdown 或 HTML 表格。
- 重建结果不存在明显的重复表头、丢行或列顺序错乱。
- 每个最终结果可以追溯到对应切片及原始 API 响应。

### 里程碑 3：本地评测与实验管理

目标版本：`v0.4.0`

任务：

- 从训练 ZIP 读取标准 Markdown 标签和文件映射。
- 根据官方评分逻辑实现本地评测；若官方实现不可得，则建立可解释的代理指标。
- 将图片参数、切片参数、API 响应、重建结果和分数绑定为一次实验。
- 输出逐样本分数、整体统计和失败样本列表。
- 增加小规模回归样本，防止优化某类表格时破坏其他文档。

验收标准：

- 一条命令可完成训练集子集预测与评测。
- 不同参数方案可以通过统一报告进行比较。
- 核心解析与重建逻辑具备覆盖正常和异常情况的测试。

### 里程碑 4：A 榜生产运行

目标版本：`v0.5.0`

任务：

- 根据训练集实验选择默认切片和重建策略。
- 对 A 榜 50 张图片分批预测，失败样本自动进入重试队列。
- 增加输出完整性检查：文件名、行数、空结果、截断响应和表格闭合。
- 明确模拟提交 100 行与 A 榜 50 张图片之间的提交规则。
- 固化最终配置，并生成提交文件和运行报告。

验收标准：

- 50 张 A 榜图片均有非空、语法有效的解析结果，或有明确的人工复核记录。
- 提交 CSV 通过本地格式和完整性检查。
- 从空缓存开始可以按照文档复现最终结果。

## 后续优化

完成首个有效提交后，再根据榜单反馈评估：

- 内容感知切片和表格线检测。
- OCR 结果与 FinixDoc-VL 结果的融合校验。
- 针对数字、金额、百分号和金融易混字符的后处理。
- 多次 API 结果投票或低置信度样本重跑。
- 并发请求、全局限流和更细粒度的任务队列。
- 人工复核工具与差异可视化。

## 工程约定

- 原始数据统一放在 `data/raw/`，不提交到 Git。数据下载地址：https://tianchi.aliyun.com/competition/entrance/532490/information
- 生成结果统一放在 `outputs/`，不提交到 Git。
- Python 源码统一放在 `src/afac_pipeline/`。
- 新增核心行为时同步增加测试。
- 有效 API 结果必须先通过完整性检查再写入缓存。
- 每次正式实验记录代码版本、运行参数、样本范围和输出路径。
