# AFAC OCR Pipeline 冲分计划

## 总体策略

当前 `submission_v033.csv` 的 A 榜成绩为 **49.5535**，对应现有 `baseline_v1`。主要问题不是提交格式，而是：

- 表格路线优先选取小范围 anchor crop，容易只识别局部内容。
- 表格修复使用“字符数增长”判断优劣，无法判断是否覆盖完整表格。
- 超大表格拼接后可能存在漏列、漏行、重复上下文和格式偏差。
- 长文档目前主要依赖固定纵向切片，边界去重和嵌入表格处理较弱。
- 当前 4b00 实验缓存曾产生 35–555 字符的退化结果，说明必须建立训练集闸门。

优化顺序固定为：**表格完整性 > 长文档切片/去重 > 候选路由与自动选择 > B 榜泛化稳定性**。

## 2026-07-20 表格 Probe 记录

- 开发集样本 `015bd47c-7034-4532-a2f0-9d177d44b22b.jpg` 的 Ground Truth 含 214 行、17,013 个单元格、229,533 个字符；`2800x4200` coverage 只得到 `1x2` tile，截断后回退 anchor，proxy 为 `20.4361`。
- `1500x1200` tile 在约 70 秒后仍返回未闭合 fence；宽松读取只有 11,255 字符、2 个表格行，且末尾截在单元格内，不能作为有效结果。
- 该类上三角费率表存在仅含网格线的空区。切片现记录“去除长横竖表格线后的文字密度”，CLI/实验默认跳过文字像素少于 10 的 tile；在上述样本的 `11x4` 网格中可安全省去 4 个纯空 tile。它只用于减少无效调用，不可替代更小的有效 tile。
- 对多 tile 实验，命令行默认 API 间隔为 12 秒；重试日志保留具体错误，HTTP 429 采用指数退避。下一个候选仍需在真实 API 可用时比较更细的有效 tile 与运行时间，不能接受自动补齐后的截断输出。

## 第一阶段：建立可比较的实验闭环

新增一个训练集实验入口，输出以下 artifacts：

- `predictions.csv`
- `metrics.csv`
- `manifest.json`
- `errors.csv`

`manifest.json` 记录路由版本、图像参数、切片参数、API 调用数、缓存命名空间和运行时间，保证每个候选可以复现。

训练集固定划分：

- 开发集：40 张，长文档/表格各 20 张。
- 冻结验证集：40 张，长文档/表格各 20 张。
- 剩余 120 张只用于最终候选 sanity check，不参与参数选择。

划分按图片宽高比、像素规模、Ground Truth 长度、表格规模分层；能识别文档标题或产品族时，尽量避免同一文档族同时出现在开发集和验证集。

候选晋级条件：

- 冻结验证集总分提升至少 2 个百分点；
- 长文档和表格两个分组都不能下降超过 1 个百分点；
- 空结果、截断结果、未闭合表格必须为零；
- API 调用量和运行时间必须记录并满足 3 小时交付约束。

本地单测不扩展为重点，只保留真实图片 smoke run、提交校验和核心拼接回归检查。

## 第二阶段：重做表格 OCR Pipeline

### 1. 从 anchor-first 改为 coverage-first

对疑似表格图片不再因为某个 800/600 像素 crop 输出“足够长”就直接接受。

新的路线：

1. 低成本读取图像 profile。
2. 检测内容边界和表格主体区域。
3. 根据目标 tile 尺寸自动计算行列数。
4. 对整个表格区域执行二维覆盖切片。
5. 只跳过确定在内容区域之外的空白 tile。
6. 对非首行 tile 重复顶部表头，对非首列 tile 重复左侧关键列。
7. 按行优先、列顺序重组。

切片数量不再固定为 `4x4`，而是根据原图尺寸和内容区域动态决定。初始候选范围：

- 单 tile 宽度：约 1,800–3,500 原图像素；
- 单 tile 高度：约 2,500–6,000 原图像素；
- 重叠范围：tile 尺寸的 3%–8%；
- 对极宽表格优先增加列数，而不是整体缩小图片。

### 2. 基于结构选择结果

表格候选选择改为综合评分，不再使用字符数作为主要依据。评分包含：

- 识别出的行数、列数和单元格数量；
- 各 tile 的行列一致性；
- 首行表头连续性；
- 左侧关键列连续性；
- 表格开始/结束是否完整；
- 重复行、重复列和重复上下文比例；
- 是否存在响应截断迹象；
- 图像覆盖区域与 OCR 输出规模是否匹配。

字符数只能作为辅助指标，禁止用“更长就更好”的规则。

### 3. 保留 Ground Truth 的 HTML 表格形态

训练集 Ground Truth 中表格主要是 HTML `<table>`，因此：

- 不再把 HTML 表格无条件转换成 Markdown pipe table；
- HTML 输入优先输出 HTML；
- 拼接时保留表格外的标题、单位说明和正文；
- `rowspan`、`colspan` 不能在不必要时被展开丢失；
- 不用 HTML 注释记录切片坐标，因为这些注释可能直接影响线上文本编辑距离。

自动补齐 `</table>` 时必须保留“曾经补齐”的状态，不能仅凭标签平衡就接受候选；如果最后一个单元格、表格行或数字序列明显未完成，应判定为截断。

## 第三阶段：优化长文档 OCR

长文档使用几组通用参数在开发集上比较：

- 切片高度：`8000`、`10000`、`12000`、`16000`；
- 重叠：约 `3%`、`5%`；
- 原图宽度保持可读性，不以过度缩放换取单次调用；
- 优先在空白段、段落间隔或横向分隔线附近调整边界。

合并逻辑改为块级去重：

- 先分离标题、正文段落、列表、HTML 表格和表格外说明；
- 边界处使用精确匹配和高相似度匹配；
- 只有在连续多个块同时重复时才删除；
- 不删除正文中合法重复出现的标题、编号或保险条款；
- 对跨 slice 的 HTML 表格执行表格级合并；
- 保持阅读顺序，不插入调试注释。

最终候选需要重点检查：

- 是否漏掉每个 slice 的末尾段落；
- 是否重复 slice 边界内容；
- 是否把嵌入表格拆成乱码；
- 是否出现 heading 层级漂移；
- 是否出现自动补齐导致的假完整结果。

## 第四阶段：通用路由和低置信度重试

新增基于图像特征的 `DocumentProfile`，不使用 UUID、文件名或 A 榜目录名：

- 原图宽度、高度；
- 宽高比；
- 总像素数；
- 内容边界；
- 内容密度；
- 横向/纵向投影特征。

路由规则：

- 极高纵横比图片进入长文档路线；
- 近方形或宽表格图片进入表格路线；
- 落在边界区间的图片先做低成本探测，再选择路线；
- 不依赖 `long_rest_A` 这样的数据集路径字符串；
- 同一套规则必须可以直接用于未来 B 榜目录。

所有样本默认只走一次主路线。只有以下情况才启动第二候选：

- 输出过短；
- 输出规模与图像规模严重不匹配；
- 表格行列不一致；
- 末尾疑似截断；
- slice 之间重复率异常；
- 结构解析失败。

低置信度候选可以回退到当前 baseline，确保新策略不会让困难样本变成空结果。

## 第五阶段：候选提交和防过拟合流程

固定保留当前 `v033` 作为安全基线，不覆盖旧缓存和旧提交。

每个新版本必须经过：

1. 开发集调参；
2. 冻结验证集确认；
3. 全部训练集分布 sanity check；
4. A 榜提交；
5. 只有总分和本地验证方向一致时才保留。

禁止以下做法：

- 根据单个 A 榜 UUID 写特殊规则；
- 针对某张图片固定输出或固定拼接；
- 只根据 A 榜样本长度调阈值；
- 为了线上分数牺牲训练集中的某一类文档；
- 用当前 100 张 A 榜图片的具体尺寸写路由分支。

建议版本顺序：

- `v034`：只修复表格 coverage-first 和候选选择；
- `v035`：加入表格结构拼接、HTML 保真和上下文去重；
- `v036`：加入长文档块级去重和嵌入表格处理；
- `v037`：加入低置信度二次路线和通用 profile 路由。

### B 榜稳定化：本地 OCR 缓存坐标绑定

- 本地 RapidOCR 的缓存键此前只含 tile 的行列编号。内容边界或网格参数变化后，旧 TSV 仍可能被读取并投射到新的源坐标，形成“运行成功但列/行整体错位”的静默错误。
- `rapidocr-v4/root_tile_manifest.json` 现绑定每个根 tile 的原图坐标、尺寸和图像字节 SHA-256；缓存重放只有在完整清单完全相同时才允许继续。已有 TSV 但缺清单的历史缓存会要求重跑到新目录，而不是猜测其几何来源。
- 这一保护与具体样本、榜单和文件名无关；它使离线训练评估、候选生成和生产 Pipeline 共享同一套可复现坐标前提。对应的单元测试覆盖“同 tile 名但不同裁剪几何”的拒绝路径。

### B 榜 v33：按单元格对齐方式自适应的坐标晶格

- `v31` 的线上分数为 `45.9023`，相对 v17 的 `45.8110` 只有 `+0.0913`，不足以支持继续以局部输出修补为主。对一张与训练集同尺寸（`4678×3308`）的双费率表进行坐标审计后，定位到本地 OCR 的表示层根因：RapidOCR 缓存将每个文字框序列化为 **中心 x 坐标**，但金融金额通常右对齐；同一物理列中，`242.8` 与 `1967.09` 会因字宽不同而拥有不同中心点。旧重建器据此把一列裂成多列，并把年度表头错误平移到负数起点。
- 重建器不再假设一个全局对齐方式。对每个已通过语义表头、年度序列和正文晶格护栏的候选表，分别以框的左边界、中心和右边界构建坐标晶格，按“年度起点合法、可见年度序列、覆盖率、已填单元格数”选择结果。该选择只依赖当前表内的文字框几何，不绑定 UUID、标题、榜单或文件名。相邻的对角角表头也必须同时看见右侧连续的 `1..5` 年度轴才允许进入候选；数字中的 `176. 61` / `1, 234` OCR 间隙会在数值单元格层归一化，裸数字间空格仍拒绝拼接。
- 同构训练页用已有 RapidOCR 缓存重放：输出 `93×77` 矩阵，代理文本 `98.7196`、阅读顺序 `61.4865`、表格结构 `100.0`、综合 `86.7354`，与改动前持平而非只在 B 页生效。新增右对齐变宽数字列、对角角表头、带小数/千分位间隙的回归测试。
- 基于同一通用重建，在 B 的双表页恢复两张从 `0` 起始的合法表：`105×80` 与 `57×81`；该页输出由 v31 的 `2,850` 字增至 `86,189` 字。生成 `outputs/submission_b_v33_adaptive_anchor_candidate.csv`，仅覆盖这 1 行：100 行、纯 pipe Markdown、HTML 标签为 0、最大字段 `184,673` UTF-8 字节、目标字段无重复非空行，严格 B-list 与 `200KB` 字段门通过，SHA-256 为 `2995c69c0761c3f1b85b6df4044522b3683c5243b39851b988d082f6baa1fcae`。这是经过训练同构验证和平台兼容性审计的候选，但 B 真值不可见，线上分数仍不能保证；此前含负年度表头的早期 v32 产物明确不得提交。

### B 榜 v34：超长窄页的内容覆盖回退（开发中）

- B v33 的覆盖审计发现另一类系统性问题：两张宽度 `1500px`、高度 `71,178/148,548px` 的长页远程输出仅 `2,973/3,663` 字，文字密度为 `0.042/0.025`。训练集中存在同宽高的 `1500×148,548` 长页，真值为 `28,760` 字，故这些输出不是短文档，而是整段漏检。
- 原架构把 RapidOCR 的所有坐标观察值直接送进数值矩阵重建；对于普通条款正文，这既会把无关文本投入昂贵的表格搜索，也没有可用的线性阅读流出口。现将“逐 tile、带几何绑定缓存的 OCR 观察值”与“规则数值表晶格重建”拆开，并增加单列正文阅读序渲染器：按 y/x 聚合、按框重叠去除相邻 tile 的同一行、保留置信度较高的变体，再将物理换行收为逻辑段落。它不按标题或 UUID 定制内容。
- 同规格训练页的完整本地 OCR 产出 `26,415/28,760` 字，文本相似度 `93.02`；这是内容覆盖的直接证据。它仍不能替代结构化远程 Markdown：本地代理中的表格结构为 `0`、阅读顺序为 `22.34`，所以只允许作为远程密度异常低时的回退，绝不覆盖正常远程页。
- 新建 `b-generalization-v6`：仅在 `>=100MP`、宽度 `<=2000px`、远程文字密度 `<0.06` 的长页启用本地 CPU RapidOCR；本地输出必须密度 `>=0.08`、比远程至少多 `1000` 字且重复率不超过既有门。长文本选择门与表格候选分数已分离：远程小表残片不能再错误拒绝大量经验证的正文恢复。B 仅命中两页，离线重建分别为 `26,415` 与 `12,813` 字；生成 `outputs/submission_b_v34_local_long_text_candidate.csv`，仅覆盖这两行：100 行、无 HTML、最大字段仍为 `184,673` UTF-8 字节，严格 B-list/200KB 门通过，SHA-256 `24ae74b6ad3e5868a05c2c9045097c8c4dccc04f555213ddff0929f842961123`。训练证据支持其内容覆盖，但本地读序/表格结构仍弱于正常远程 Markdown；它因此是一个有针对性的候选而非对线上涨分的保证。
