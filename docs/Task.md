一、 任务介绍
在金融行业中，沉淀了海量的核心业务信息（如保险条款、费率表等）。这些文档通常具有非标准化、高内容密度、复杂版式结构（多级标题、嵌套表格、批注、多栏排版、跨页图表等）的特点。

本赛题旨在攻克传统 OCR 易割裂语义、传统版面分析在非标排版下鲁棒性不足的行业痛点。本赛题要求参赛者基于主办方提供的多模态底座与工具链，构建一套具备感知、切块、重组、去重与纠错能力的多模态文档解析工作流（Workflow）。针对超长或超大金融文档截图，系统需自动化解析并输出与原文严格对应的完整、高质 Markdown 文本，实现高精度、高保真的文档解析。

二、 任务目标
参赛选手需要设计并实现一个端到端的文档解析系统，在给定的算力与模型约束下，解决超大图像带来的内存溢出（OOM）、视觉长上下文受限、切块拼接处的文字重复/截断等工程痛点，最终达到以下四大核心目标：

内容完备性（Completeness）： 100% 覆盖原始图片中的所有有效文本、表格、脚注及特殊符号，严禁漏检与幻觉。
结构高保真（Structural Fidelity）： 精准还原多级标题层级（# 至 ######）、段落嵌套、无序/有序列表及标准的 Markdown 表格（Table）。
阅读流顺序（Reading Order）： 遵循人类真实阅读流顺序，正确处理多栏排版、跨块图表、层级嵌套等场景。
极致工程鲁棒性（Robustness）： 确保在面对密集表格、超长文档以及错行目录等场景时，系统依然具备极高的去重与还原表现。
三、 任务数据
本赛题采用 A / B 榜双阶段评测模式。赛事数据集以文件夹形式发布，包含原始图片及对应的 Ground Truth (GT) 标签文件。

3.1 数据格式
预测结果与 Ground Truth 均采用标准的 CSV 文件，包含且仅包含以下两个字段：

字段名称 类型 说明 示例
file_name String 测试集图片文件名（含扩展名） doc_001.png
ground_truth String 与图片内容严格对应的标准 Markdown 结构化字符串 # 一 总则\n## 1.1...
3.2 评测阶段
A 榜： 提供训练集（200条）与测试集（100条）。用于选手验证算法可行性、调整切块与调度策略、在线提交并进行阶段性筛选。
B 榜： 提供全新测试集（100条），用于最终的闭源评测。

4.2 数据分布
为了全面评估解析系统的泛化能力和工程极限，本赛题的数据分布涵盖以下三大核心维度：

图像规格维度： 集中解决大图 OOM 痛点。包含大量长宽比超过 30 的“面条图”，以及分辨率极高、单页像素超过 2 亿的超大金融单页截图。
版式结构维度： 覆盖复杂多变的非标准化版面。其中包含多级标题交错、多栏排版（分栏阅读流分析）、嵌套表格、跨多页章节等。
文本语境维度： 语境高度专业。重点抽取自各大保险公司的互联网专属条款、费率精算表及特约批注，包含大量生僻缩写、条款编号及密集的特殊符号。

① 模型使用合规校验

本题旨在考查选手在受限算力与模型约束下，如何尽可能还原复杂文档结构的能力。选手在构建工作流时，禁止使用规定以外的任何外部商业或开源大模型。
线上 API 仅允许调用主办方提供的 FinixDoc-VL（开赛后会在钉钉群：179205019946 统一分发使用说明），详细调用说明见赛题页左侧目录栏 “API调用说明” 。同时，最终提交的工程中允许集成并使用不依赖 GPU 且可完全本地离线运行的轻量级辅助模型（总参数量须小于 10M）。

② 文本与结构相似度校验

线上评测系统将对提交的文本进行多维度自动化量化评估：

文本准确率： 基于字词层面的编辑距离（Edit Distance）进行精确比对。
表格准确率： 基于表格层面的 TEDS 进行评分对比。
阅读流顺序： 基于逻辑块层面的先后顺序进行比对，评估跨栏跨页阅读流的还原度。

② 指标参数释义

Text Edit（文本编辑距离归一化损失）：
用于评估字词层面的解析精准度。通过计算系统生成文本与标准 Ground Truth 之间的字级 Levenshtein 编辑距离，并除以标准文本的总长度进行归一化。漏检、错检、幻觉或接缝处的重复识别均会导致得分降低。

Table TEDS（表格树编辑距离得分）：
针对金融保险文档中大量非标、密集的表格组件进行专项评估。采用国际通用的 TEDS (Tree Edit Distance for Structure) 算法。该指标不仅比对表格内部文本的准确性，更将 Markdown 表格转化为树状结构，严格匹配单元格（Cell）的合并、嵌套、跨行/跨列等拓扑结构的正确性。满分为 100 分。

Read Order Edit（阅读流编辑距离得分）：
用于评估多栏排版、嵌套图表等复杂场景下的文本阅读流先后顺序。将模型生成的文本按逻辑块切分，计算其与 Ground Truth 在块级别阅读流顺序上的 Levenshtein 编辑距离。该项指标旨在考查系统是否遵循了人类的真实阅读顺序。
